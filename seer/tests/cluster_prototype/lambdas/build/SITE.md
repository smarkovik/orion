# Public site: contract

The build Lambda renders a public, static website next to the existing analysis pages, which move to `/lab/`. Settings and all interface text are in `site.yaml`; the brand name is a codename and appears nowhere else.

**Readers:** non-technical, mostly 30–60. The UI is clean and simple and shows what happened: a picture and a title per story, how many outlets covered it, and links to read more at the outlets. Large type, high contrast, big tap targets, no jargon, no tiny chips. Light and dark themes: follow the system, with a toggle that remembers the choice. Mobile first. No search; history is browsed by day.

- **Week ranking**: the `top` lists (up to `limits.week` story summaries each) of the week's days, merged, de-duplicated by story id (the newer day wins), sorted by source count, size, `first_published`; top `limits.week`. Live days (still in the window) are recomputed from the window, older days come from `days.json`.
- **Since your last visit** (browser only): every card carries `data-created` (story `created_at`). `site.js` keeps `{prev, last}` in `localStorage` key `{brandslug}:visit:{edition}`; a visit more than 30 minutes after `last` makes `prev = last`. With a `prev`, cards created after it get the `new_for_you` label, the server "new" marker is hidden and the front page shows a one-line count. First visit: nothing marked.
- **Outlet logos**: `build/logos.py` `ensure(sources, now) -> {domain: key|None}` saves each outlet's best homepage icon (apple-touch-icon > largest `rel=icon` > `/favicon.ico`, SVG skipped) as a 64×64 transparent PNG at `logos/{domain}.png` (30-day cache header). `state/logos.json` in the raw bucket (`{domain: {fetched_at, ok}}`): refetch after 30 days, retry failures after 7, otherwise no network; never raises. Cards show up to 3 overlapping round logos of distinct outlets plus `+N`, story rows and the about page show a logo before the name; an outlet without a logo gets a round initial. Logos have `alt=""`. `render_edition(..., logos=None)`.
- **Developing**: a story with ≥ 2 articles published in the last 2 hours (build `now`) and ≥ `min_sources` sources gets the marker `developing` (a small dot, pulsing only without `prefers-reduced-motion`). One marker per card: developing > new > updated; the browser's "new for you" label never replaces or hides it.
- **Follow a story** (browser only): button on story pages. `localStorage` `{brandslug}:follow:{edition}` = `{storyId: {at, n}}` (`n` = articles seen). On any edition page with follows, `site.js` fetches `follow.json`, shows a notice (`follow_notice_one` / `follow_notice_many`) listing stories whose size grew, with `+N`. Opening a followed story sets `n` to its size. Follows older than 7 days or missing from `follow.json` are dropped; at most 50.
- **Display panel**: the "Аа" button in the header opens a panel with text size (100 / 115 / 130 % of the root font; all type is `rem`) and pictures on/off. Stored in `localStorage` (`textsize`, `images`) and applied before paint as `data-text` / `data-images` on `<html>`. Images are always `loading="lazy"`, so with pictures off (blocks hidden) no thumbnail or logo is requested.
- **Share** on story and week pages (hidden without JS): `navigator.share` when present, otherwise links to the `share_targets` of `site.yaml` (the page URL appended, encoded) and "Copy link". Story pages carry Open Graph tags; `og:url` and `og:image` only when `base_url` is set.
- **Install**: every page links its edition's manifest (the chooser none), `theme-color` for light and dark, `apple-touch-icon` and the iOS/Android web-app metas. The about page has a short "add to home screen" tip (`install_tip`).
- **Links are relative and name the file** (`../story/12.html`, `2026/11/15.html`), so the site works opened from disk, on S3 behind CloudFront and as a shared preview. No absolute paths, no directory URLs.
- **Single-source stories have no story page**: their card links straight to the article.
- **Top of the day** = open or archived stories in the window whose `first_published`, in the edition's time zone, falls on that day, with ≥ `min_sources` sources, ranked by source count, then size, then `first_published`.
- **Thumbnail missing** (`thumb_key` empty): a calm placeholder block, never a broken image. Images get `alt` = the title, `loading="lazy"` (except the lead), and width/height so the layout doesn't jump.
- **Times** are shown in the edition's time zone and language: `14:20` for today, `15 ноември, 14:20` / `15 novembre, 14:20` otherwise. Dates use `months` and `weekdays` from `site.yaml`.
- **Cache-Control** from `cache_seconds`: `html` for pages and feeds, `past_day` for day pages older than yesterday (never re-rendered anyway), `asset` (+ `immutable`) for hashed assets and thumbnails.
- No external requests: no web fonts, no CDNs, no trackers. System font stack.

## Modules

| File | Owner | Holds |
| --- | --- | --- |
| `build/model.py` | fixed | `Story.thumb_key`, `thumb_src`, `thumb_source`; `days_key(edition)` |
| `build/web/` (`render.py`, `templates/`, `static/`) | web agent | `selection(window, cfg, now) -> list[str]` (story ids that any page rendered this run will show), `day_stories(window, day, cfg) -> list[Story]` (the ranking above; `day` is a `date` in the edition's time zone), `render_edition(window, cfg, now, days, sources, touched, logos=None) -> list[Page]`, `render_root(cfg, summaries, now) -> list[Page]` (chooser, robots, sitemap), `render_assets(cfg=None) -> (list[Page], css_key, js_key)` (CSS, JS, icons, `sw.js`; `cfg` supplies the brand and colours). `Page` = `(key, body: bytes, content_type, cache_control)`. `cfg` = parsed `site.yaml` plus `"edition": code`. `days` = the edition's days index (below). `sources` = `{domain: name}` from `sources.yaml` |
| `build/thumbs.py` | thumbs agent | `ensure(window, story_ids, now) -> dict` (counts: fetched, reused, failed, skipped): for stories with `thumb_key is None`, try the label article's `image_url`, then the other members' images (newest first); download (honest user agent, 10 s timeout, ≤ 8 MB, `image/*` only), cover-crop to 16:9, resize to 640×360, WebP quality 72, upload to the site bucket; set `thumb_key`, `thumb_src`, `thumb_source` (the article's domain). If none works, `thumb_key = ""`. Up to `THUMBS_PER_RUN` (default 80) downloads per run, 8 in parallel, at most 2 at once per host |
| `build/admin.py` | admin agent | `summary(manifest, window, now, build, cfg) -> dict` (the compact run summary: scrape per source incl. `new`, build counts, story buckets and top 5, site counts, `cost` from the `admin:` section of `site.yaml`), `record(edition, summary, cfg, now)` (day file + index; never raises), `publish_static()` |
| `build/logos.py` | thumbs agent | Outlet logos (see above) |
| `build/days.py` | thumbs agent | `update(window, cfg, now, previous) -> list[dict]` maintaining `state/{edition}/days.json`: one entry per day, newest first, `{"date", "stories", "lead_title", "lead_story", "lead_thumb", "top"}` (`top` = up to `limits.week` story summaries `{id, title, thumb, sources, size, first_published, page, url, section}` from `web.render.story_summary`; entries without it still work), updated for today and yesterday using `web.render.day_stories`; kept 3 years |
| `build/render.py` | thumbs agent | Lab pages: same as now, keys under `lab/` and `noindex` |
| `build/handler.py` | thumbs agent | After assign and prune: `selection` → `thumbs.ensure` → `days.update` → `render_assets`, `render_edition`, `render_root`, lab pages → upload every `Page` with its content type and cache header → save `days.json` with the window → admin summary (`admin.summary`/`record`/`publish_static`, failures are logged, never fail the build) |

## Local run

`fn-build` now needs the internet for thumbnails. Behind the proxy it runs like `fn-scrape`: host network, proxy env, `NO_PROXY=127.0.0.1,localhost`, S3 at `http://127.0.0.1:7070`, the emulator on `0.0.0.0:9102` and its runtime API on `127.0.0.1:9003` (host-network emulators clash on the default 9001). `make preview` serves `data/s3/seer-site/` at http://localhost:8090.

## Retention

Site bucket lifecycle: `{e}/story/`, `{e}/20*` (day and month pages), `{e}/week/` and `{e}/briefing/` and `thumbs/` expire after 1,095 days (3 years), like the archive.
