Seer infrastructure on AWS — plan and cost

2026-11-15 (database-free revision) · Live version: claude.ai artifact

At a glance

About $2.20–2.55 a month at 1M views, and about $29 for the first year, in Frankfurt. There's no database, no VPC and no NAT gateway: two Lambdas and S3.

  • Pipeline: every hour from 08:00 to 22:00, scrape → S3 raw batch → build → static pages on S3 and CloudFront. The new batch in S3 triggers build.
  • No database. Each edition's working state is one file in S3: the last 48 h of articles with their vectors, plus the open stories. Build loads it, updates it and saves it back.
  • The record: every fetched page stays gzipped in S3, tiered down to Deep Archive and deleted after 2 years. Processed articles and stories go to an archive in S3 for 3 years.
  • Updates are bumped, not reprocessed. Only new articles are embedded; an edited article just raises its story.
  • Same stories as the Postgres version: identical for mk, and 91.8% pair agreement for fr, with the gap explained by input differences. Tested locally with real Lambda images; prototype in PR #16 and its successor.
  • Ads, best guess: about $240–1,200 a month at 1M views, depending on the mk/fr mix and AdSense approval.

Architecture

Scrape is the only part that talks to news sites. Build needs no internet: it reads and writes S3 only. Readers never touch either Lambda; they get static pages from CloudFront.

How an hourly run works

EventBridge Scheduler starts scrape at the top of every hour from 08:00 to 22:00, Skopje time, once per edition. That's 15 runs a day per edition, about 450 a month each.

  1. Scrape (Lambda 1). Reads state/{edition}.json.gz to see what's already known, then fetches only what's new:
    • WordPress sites (mk): posts created or edited since that site's last good run (modified_after, also checked on our side because some sites ignore it).
    • News-sitemap sites (fr): article pages it hasn't seen, plus a capped re-check of recent articles to catch edits.
    • It writes everything it fetched, raw API JSON and raw HTML, to S3 as one gzipped file per edition per run. Then it writes a small manifest, runs/{edition}/{run}.json.
  2. Build (Lambda 2), triggered by the manifest's S3 event. One build runs at a time. Each build:
    • Loads the edition's window (about 5–7 MB).
    • Parses the raw batch: text, images, categories. A new title, or more than 5% of the text changed, marks an article as updated.
    • Embeds new articles only and adds each to an open story, or starts a new one.
    • Renders Top and Latest pages and uploads them to the site bucket.
    • Writes back the window, the scrape state, an archive file and a build report.

Updates are bumped, not reprocessed. An edited article keeps its first embedding and its story. Its story only gets a new activity time, so it rises in Top.

Replays are exact. Build uses the scrape's own clock, so replaying the raw batches rebuilds the same window and pages. If extraction or clustering improves, the state can be rebuilt from S3 without scraping again.

Storage and retention

S3 raw bucket

Prefix Holds Kept
raw/{edition}/{YYYY}/{MM}/{DD}/{HH}/{run}.jsonl.gz Everything fetched in one run: raw WordPress JSON or raw HTML, gzipped 2 years
runs/{edition}/{run}.json Scrape manifest; its creation triggers build 2 years
archive/{edition}/{YYYY}/{MM}/{DD}/{run}.jsonl.gz Articles inserted or changed in the run (full text) and stories created, changed or closed 3 years
builds/{edition}/{run}.json Build report: counts, timings, page sizes 2 years
state/{edition}/window.json.gz Hot state: the last 48 h of articles with vectors, and open stories (5–7 MB) Overwritten every run
state/{edition}.json.gz What scrape has already seen Overwritten every run
  • Compressed when written. Batches are gzipped before upload, so there's no second write and no delete.
  • Path to Glacier: S3 Intelligent-Tiering moves an object to Infrequent Access after 30 days without reads and to Archive Instant Access after 90 [12]. The two optional archive tiers are on: Archive Access after 90 days and Deep Archive Access after 180 days. Objects under 128 KB are never moved [12], so one batch per edition per run keeps raw objects large.
  • Expiry: lifecycle rules delete raw/, runs/ and builds/ after 730 days, and archive/ after 1,095 days.
  • History queries: the archive is gzipped JSON lines, queryable with Athena or DuckDB when needed. If queries become regular, compact it into monthly Parquet files.
  • Config files: infra/s3-raw-intelligent-tiering.json, infra/s3-raw-lifecycle.json, infra/s3-raw-notification.json, infra/scheduler.md.

Everything is in Frankfurt (eu-central-1). No VPC, no NAT, no database, no Step Functions.

Run budget

Measured on the local Lambda simulation: real images, Lambda memory limits, a read-only filesystem [13].

Run Scrape mk Scrape fr Build mk Build fr
Hourly batch (02:31, quiet) 5 s 51 s, 5 new and 105 re-checks 0.8 s 7.2 s
Live, 7.5 h of morning news 5 s, 77 records 165 s, 278 records 16 s, 69 new 77 s, 278 new
48 h backfill 10 s 382 s 260 s 363 s
  • About 165 GB-s per hourly run (both editions, cold starts included), or about 75,000 GB-s a month: 19% of Lambda's free 400,000.
  • Peak memory: scrape about 330 MiB, build about 1.1 GiB.
  • Raw batches: about 7–11 MB gzipped per French run and under 0.2 MB for mk, so 3–5 GB a month.
  • Windows: 5.4 MB (mk) and 6.8 MB (fr), gzipped. Pages: 20–40 KB gzipped, 60 stories each.
  • Backfills fit Lambda's 15-minute limit: a 48 h French backfill builds in about 6 minutes.

Revenue with Google ads (best guess)

I found no published AdSense rates for news websites in France or North Macedonia; searches only turned up YouTube figures, which don't carry over. The rates below are my estimate from general industry knowledge. Treat them as a range to test with real traffic, not a forecast.

Readers Revenue per 1,000 page views (after consent refusals and ad blockers) 500k views 800k views 200k views
France (fr) $0.80–2.00 $400–1,000 — $160–400
North Macedonia (mk) $0.10–0.40 $50–200 $80–320 —
Total per month 50/50 split: about $450–1,200 80% mk, 20% fr: about $240–720
  • Ads don't change the infrastructure bill. Google serves the ads and their scripts, not our CloudFront.
  • Break-even is tiny. At about $2.50 a month, a few thousand French views cover the bill.
  • Approval is the real risk. Google's policies bar ads on scraped content [15]. A page of headlines and outbound links can be rejected as "low value content". The pages need value of their own: grouped stories, source counts, timelines, and ideally short original story lines.
  • French readers need a consent banner. Google's own consent tool is free. Readers who refuse get fewer, cheaper ads, which the fr range above assumes.
  • In North Macedonia, direct sales probably pay better. Selling banners to local advertisers likely beats AdSense at Balkan rates.

Notes and risks

Legal and access (these matter more than cost)

  • Images at 1M views. The pages load photos straight from the outlets' servers. At 10–20 images per view, that's 10–20M image requests a month on 20 outlets, and the no-referrer setting hides that they come from us. Hosting thumbnails ourselves fixes the bandwidth problem but copies licensed photos. Decide before launch.
  • robots.txt must be obeyed before anything is public. The prototype ignores it for experiments only.
  • Ads change the legal picture. Google's policies bar ads next to scraped content [15]. Commercial use of French headlines and snippets also falls under the French publishers' neighbouring right (droit voisin).
  • The raw archive is a copy of publishers' pages, kept for internal use only and never republished. EU text-and-data-mining rules let publishers opt out, and many French ones do. Check with counsel before launch.
  • No fixed outbound IP. Scrape uses AWS's shared addresses; sites that block AWS ranges will block us.

Without a database

  • The window file is the single source of truth. Turn on S3 versioning for state/ with a 7-day expiry of old versions, so a bad build can be rolled back. A lost window can also be rebuilt by replaying the raw batches.
  • Builds must not overlap. Reserved concurrency 1 queues them, and the conditional write catches anything else.
  • Bring a database back when a live feature needs one: search over history, related past stories, an API, or user accounts.

Data quality and runtime

  • Edited articles are never re-embedded. That's cheap and stable, but a live blog that drifts to a new topic stays in its first story.
  • Le Figaro raises false "updated" flags (17 of 111 in testing). With update bumps, its stories would float up every hour. Normalize its text before comparing.
  • The build cold-starts every run. Loading the model adds about 6–8 s, which is acceptable at this volume.
  • Overnight catch-up is automatic: scrape asks each site for everything since its last good run.

Operations

  • Re-ingesting old runs after 90 days needs a restore from the archive tiers first, which takes hours.
  • Alarms: build errors, and a site older than 2 hours.

Options we rejected

Option Why not
Aurora Serverless v2 (Postgres) $5–8.50 a month for a database that only the hourly build touches. It needs a VPC and resumes in about 15 s. The working set is about 6 MB per edition. Add it back when a live feature needs it.
NAT gateway for Lambdas in a VPC About $44 a month in Frankfurt [1][6], just for internet access. Gone with the VPC.
NAT instance, RDS Data API, public Aurora Workarounds for a database we no longer have.
IPv6-only outbound traffic Only 10 of our 20 sources have IPv6 addresses [11].
One small VM running Docker Compose About $10–15 a month and a machine to patch. Now four to six times the serverless bill.

Open decisions

  1. Images. Keep loading them from the outlets' servers, host our own thumbnails, or show none.
  2. French re-check cap. Re-check 5 or 20 recent articles per site each hour. It sets scrape time and how quickly French edits show.
  3. Archive format. Gzipped JSON lines now; monthly Parquet once history queries are regular.
  4. Ads. AdSense, or direct sales to local advertisers. The site needs a consent banner either way for French readers.
  5. Region. Frankfurt or Paris. The prices here are Frankfurt.
  6. Infrastructure as code. CDK or Terraform.
  7. Domain. A .mk, .fr or neutral domain.
